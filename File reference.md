## Differences from the guide snippets

The step snippets show the pattern; the reference adds what a complete, working app needs. If your code matches a step snippet but not the reference, these are the reasons.

- **Modal:** reads `onClose` through a ref, so a parent's inline `onClose` no longer steals focus on every keystroke. It also gains a close button.
- **store.ts:** listeners are created per store, and `configureApiClient` runs inside `setupStore`, so each test store gets its own wiring. It adds theme persistence, an error toast for failed mutations, and a cache reset on logout.
- **router.tsx:** the dashboard moves to `projects/:projectId/dashboard`, and the activity, kit and not-found routes are added.
- **types/api.ts:** adds `ProjectInput`, `TaskInput` and `TaskComment`; `updateTask` takes `Partial<TaskInput>`.
- **Mocks:** fixed seed data replaces faker, matching the backend seeder, and latency is set to 0 in tests.
- **tsconfig.app.json:** the `@/*` path is written without `baseUrl`, which newer TypeScript versions deprecate.
- **Backend:** `UpdateTaskRequest` gains `description`, `TaskService` takes a `UserRepository` for assignees, comments get their own service and controller, and `FieldValidationException` covers business rules such as duplicate project keys. Null fields are omitted from JSON, and table names avoid reserved words.
